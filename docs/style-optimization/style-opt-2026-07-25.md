## 关键技术决策

### 决策 1：使用 `:has()` 选择器识别 2★ 状态
- **问题**：原组件未在 `.win-card` 上附加星级类，无法直接通过类选择器识别 1★/2★/3★
- **方案**：`.win-card:has(.star-filled:nth-child(2)):not(:has(.star-filled:nth-child(3)))` 通过子元素星星数量推断 2★
- **收益**：无需改动 TSX 即可实现星级联动；现代浏览器（Chrome 105+、Safari 15.4+、Firefox 121+）原生支持

### 决策 2：触摸反馈使用 `@media (hover: none)` 而非 `@media (max-width)`
- **问题**：部分桌面触屏设备宽度大但无 hover，移动端折叠屏宽度可能很大
- **方案**：通过 `hover: none` 和 `pointer: coarse` 双重判断设备类型
- **收益**：精准识别触摸设备，不影响桌面端 hover 体验

### 决策 3：传说成就使用 `[data-rarity]` 和 `.rarity-*` 双选择器
- **问题**：原组件未在成就卡片上附加 `data-rarity` 属性，但可能有 `.rarity-*` 类
- **方案**：双选择器兜底：`[data-rarity="legendary"], .rarity-legendary`
- **收益**：无论组件使用哪种方式标记稀有度，样式都能生效

### 决策 4：进度条光效使用 `::after` 而非 `box-shadow`
- **问题**：`box-shadow` 无法做横向位移动画，且会被 `overflow: hidden` 裁剪
- **方案**：`::after` 伪元素绝对定位 + `transform: translateX()` 位移动画
- **收益**：光带可在进度条内自由移动，被 `overflow: hidden` 自然裁剪

### 决策 5：背景流动使用 `background-position` 而非 `filter`
- **问题**：`filter: hue-rotate` 会影响所有子元素，性能差
- **方案**：`background-size: 200% 200%` + `background-position` 动画
- **收益**：仅影响背景层，子元素不受影响；GPU 加速合成层

### 决策 6：移动端试管缩小至 38×120px
- **问题**：380px 以下屏幕默认试管（44×140px）+ 间距可能触发横向滚动
- **方案**：极小屏幕试管尺寸 -13% / -14%
- **收益**：5 个试管 + 间距可完整显示在 360px 屏幕上

### 决策 7：桌面端试管放大至 48×150px
- **问题**：大屏上默认试管显得过小，视觉冲击不足
- **方案**：768px 以上试管尺寸 +9% / +7%
- **收益**：桌面端游戏面板有更强烈的视觉存在感

### 决策 8：签到已完成态使用 `opacity + filter` 而非 `display: none`
- **问题**：完全隐藏会让用户怀疑签到是否成功
- **方案**：`opacity: 0.78` + `filter: saturate(0.85)` 弱化但保留可见
- **收益**：用户能确认签到状态，但视觉不抢夺注意力
