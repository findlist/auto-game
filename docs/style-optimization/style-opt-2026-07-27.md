## 关键技术决策

### 决策 1：使用 `[style*="width: 100%"]` 识别进度条满进度
- **问题**：原组件通过内联 `style={{ width: `${pct}%` }}` 设置进度，无类标记 100% 状态
- **方案**：属性子串匹配选择器 `[style*="width: 100%"]`
- **收益**：无需改动 TSX 即可识别满进度；现代浏览器原生支持
- **限制**：仅匹配带空格的 `width: 100%`，组件代码使用模板字符串 `${pct}%` 生成 `width: 100%`（带空格），匹配正确

### 决策 2：传说粒子使用 `::before` 而非 `::after`
- **问题**：`.achievement-card` 可能有 `::after` 用于其他装饰
- **方案**：使用 `::before` 叠加粒子层，子元素 `z-index: 1` 确保可读
- **收益**：避免与未来 `::after` 装饰冲突

### 决策 3：帮助步骤序号使用 CSS counter
- **问题**：原 SVG 内已有数字，但视觉强调不足
- **方案**：`.help-visual-steps` `counter-reset` + `.help-visual-step` `counter-increment`
- **收益**：自动编号，无需 TSX 改动；新增/删除步骤自动重排

### 决策 4：试管焦点光环限定 `@media (hover: hover)`
- **问题**：触摸设备 `:focus-visible` 行为不一致，可能与触摸反馈冲突
- **方案**：`@media (hover: hover) and (pointer: fine)` 双重判断
- **收益**：精准识别鼠标设备，触摸设备保持原有 active 反馈

### 决策 5：空试管暗示使用 `:empty` 伪类
- **问题**：需要识别"无颜色层"的试管
- **方案**：`.tube-inner:empty::after`（:empty 匹配无子元素的容器）
- **收益**：纯 CSS 检测，无需 TSX 添加类；与已有 `.color-layer:last-child::after` 不冲突（:empty 优先级更高）

### 决策 6：模式按钮阴影使用 CSS 变量
- **问题**：原阴影固定黑色，不随主题变化
- **方案**：`:root` 定义 `--btn-shadow-color` / `--btn-shadow-color-2`，主题切换时只需更改变量
- **收益**：未来主题扩展成本低；当前默认值与主题色协调

### 决策 7：胜利卡片粒子使用 `::after` 一次性动画
- **问题**：已有 `::before` 顶部光环，需要避免冲突
- **方案**：`::after` 5 色 radial-gradient + `animation-fill-mode: forwards` 一次性 3s 动画
- **收益**：胜利时一次性的"庆祝彩屑"视觉，不持续干扰

### 决策 8：360px 极小屏单独断点
- **问题**：380px 断点对 360px 及以下屏幕仍显紧凑
- **方案**：`@media (max-width: 360px)` 在 380px 基础上进一步精简
- **收益**：iPhone SE（375px）/ Galaxy Fold（344px）等极小屏体验优化

### 决策 9：769-1024px 平板端独立断点
- **问题**：原 768px 以上直接跳到桌面布局（640px max-width + 48×150px 试管），iPad 等平板显得过大
- **方案**：`@media (min-width: 769px) and (max-width: 1024px)` 中等屏专属
- **收益**：iPad / Android 平板视觉比例更协调

### 决策 10：限时进度环使用 `z-index: -1`
- **问题**：conic-gradient 装饰环不能遮挡徽章文字
- **方案**：`::before` `z-index: -1` + `.timer-badge.timer-danger` `position: relative`
- **收益**：装饰环在徽章下层，文字始终可读
